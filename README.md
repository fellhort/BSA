# 📌 Пакет требований для фичи: Завершение поездки вне зоны парковки самоката

## 📖 Описание проекта
Данный проект представляет собой пакет требований для отдельной фичи сервиса аренды самокатов **МТС-Юрент**: 

**User Story:**
> Я как пользователь приложения МТС Юрент хочу иметь возможность завершить поездку вне зоны парковки, описав причину поломки, для того, чтобы самокат, не пригодный к использованию, не был выпущен на линию.

## 📌 Бизнес-требования <a name="business-requirements"></a>
- Описаны и защищены у эксперта **User Stories (US)** и **Use Cases (UC)**.
- Разработан макет интерфейса мобильного приложения в **Draw.io** на основе US и UC.
- Смоделирована **BPMN-диаграмма** бизнес-процессов в **Camunda Modeler**.

---
## ⚙️ Системные требования <a name="system-requirements"></a>
- Спроектирована **модель данных** в соответствии с **DDD-подходом**.
- Созданы **логическая и физическая модели данных (ERD)** для **PostgreSQL**.
- Реализованы **REST API вызовы** (создание/получение сущностей, POST/GET) в табличном виде.
- Подготовлена **Swagger-документация** для API.
- Разработана **диаграмма последовательности** взаимодействия компонентов.

---
## ✅ Критерии приемки <a name="acceptance-criteria"></a>
- Определены критерии приемки на основе сценариев **Given/When/Then**.
- Разработаны **нефункциональные требования (NFT)** к системе.

---
## 🚀 Запуск и валидация <a name="setup-and-validation"></a>
1. Развернуть **PostgreSQL** локально.
2. Импортировать схему данных (см. [Ex07_ERD.sql](./Ex07_ERD.sql)).
3. Запустить тестовые SQL-запросы для валидации модели данных.
4. Открыть Swagger UI и протестировать API.
